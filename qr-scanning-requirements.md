Source of truth: the current web implementation in this repository.

- `src/lib/qr-validation.ts` — classification + validators
- `src/components/dashboard/scan-queue-qr-dialog.tsx` — shared scanner
- `src/components/dashboard/pet-queue-checkin-dialog.tsx` — dedicated queue scanner
- `src/components/dashboard/daily-queue-qr-dialog.tsx` — station QR generator
- `src/components/dashboard/field-op-attendance-dialog.tsx` — outreach poster generator
- `src/components/dashboard/procedure-appointment-slip-dialog.tsx` — appointment pass generator
- `src/app/(dashboard)/queue-checkin/page.tsx` — clinic queue landing page
- `src/app/(dashboard)/outreach-checkin/page.tsx` — outreach landing page

- `src/lib/cvo-context.tsx` — outreach headcount + encounter recording
- `src/lib/utils.ts` — opening hours and grace period helpers

## 0. Governing rule (non-negotiable)

There are **two distinct check-in QR families**. They must never be interchangeable.

| Family | `QrCodeKind` | Destination | Effect |
| --- | --- | --- | --- |
| Barangay Field Operation attendance | `field-op` | `/outreach-checkin` | Headcount + encounter log |
| Today's Clinic Queue | `queue` **and** `appointment` | `/queue-checkin` | Queue ticket `Q-NNN` |

`appointment` is a **sub-type of the queue family** (a JSON appointment pass), not a third flow. Anything else → `unknown` → rejected. Classification lives in `parseQrCode()` (`src/lib/qr-validation.ts`) and gives **field-op precedence** over queue.

## 1. Field Operation Attendance QR

**Purpose:** record attendance at a Barangay outreach / mobile drive. It **does not** create a clinic queue ticket.

**Generated by:** staff `/field-operations` → *Attendance & QR Poster* (`field-op-attendance-dialog.tsx:108-135`).

### Encoded payload (URL, not JSON)

```
https://syncvet.cagayan-de-oro.gov.ph/outreach-checkin?type=outreach-attendance&opId=<FO-...>&barangay=<...>&date=<YYYY-MM-DD>&vet=<...>&venue=<...>
```

- `URLSearchParams`-encoded (spaces become `+`), QR rendered 400px, pure black on white, printed as a poster.
- **Contains no pet id, owner id, queue number, or appointment id.** Those are supplied after scanning.
- Origin is hard-coded to production; mobile must deep-link this URL into the in-app scanner, not open a browser.

### Where scanned

- In-app `ScanQueueQrDialog` with `expectedType="field-op"` — pet-owner dashboard (`pet-owner/page.tsx:3480,3651`) and CVO social feed (`cvo-social-feed.tsx:734`).
- Also by opening the raw URL with the phone camera → `/outreach-checkin` landing page.

### Scanner configuration

- `html5-qrcode` dynamic import.
- Rear camera: `{ facingMode: "environment" }`.
- `fps: 10`, `qrbox: { width: 220, height: 220 }`, `aspectRatio: 1.0`.
- File-upload fallback via native `BarcodeDetector({ formats: ["qr_code"] })` with 900px downscale.

### Validation rules (`validateFieldOpQr`, `qr-validation.ts:184-279`), in order

1. Reject `queue` or `appointment` → **"Clinic Queue QR Detected"** — *"...not a field operation QR. It cannot be scanned to record Barangay Outreach attendance."*
2. Reject `unknown` → **"Invalid Attendance QR"**.
3. Require `opId` → **"Missing Outreach Reference"**.
4. Match a real schedule by `opId` or `id` in `fieldOperations` → **"No Matching Field Operation"**.
5. QR `date` must equal the matched operation date → **"Attendance QR Does Not Match Schedule"**.
6. Operation date must equal **today** → **"Attendance QR Not Yet Active"** / **"Expired Attendance QR"**.
7. Reject if past the **1-day grace period**, or status `completed` / `cancelled` → **"Expired Outreach QR Code"**.
8. **No 8 AM gate.** Grace period is for staff wrap-up only; scanning is valid on the event day itself.

### On successful scan (two-phase)

1. Stop camera, show "QR Code Scanned!" overlay, toast `QR Code verified successfully!`.
2. `incrementFieldOpSlots(opId, 1)` → `field_operations.vaccinated_pets + 1` (optimistic React Query cache → localStorage `cvo_field_operations_v2` + `syncvet-field-op-updated` event → Supabase `UPDATE field_operations SET vaccinated_pets, updated_at`, keyed by UUID `id` or `op_id`).
3. Append `&autoCounted=true`, emit `syncvet-outreach-scanned` → opens post-scan form.
4. Pet owner selects **pet** and **service**: Clinical Consultation / Mass Anti-Rabies Vaccination / Free Spay & Neuter (Kapon).
5. `recordFieldOpAttendance()` (`cvo-context.tsx:1425-1514`) re-validates op/status/date, skips the second increment when `autoCounted`, inserts a **completed** `consultations` row (`service_type: "Field Treatment/Consultation"`, `status: "completed"`, `ENC-2026-#####`) and an `audit_logs` row with action `Field Outreach QR Attendance`.
6. **No navigation to the queue.** Toast: `Attendance Verified & Encounter Logged!`.

### Current web gaps to fix in mobile

- No persistent per-user / per-pet dedup — repeated scans of the same poster each increment headcount and create another encounter. Add a scan ledger keyed by `opId + petId + date`.
- Two separate writers (scanner increment + form increment) rely on the `autoCounted` flag; a raw-URL landing can double count.
- Date checks mix device-local date (scanner) with `Asia/Manila` (`recordFieldOpAttendance`) — use one authoritative clock.

## 2. Today's Clinic Queue QR

**Purpose:** check in at the CVO Carmen clinic and receive a queue ticket. It **does not** record outreach attendance.

### Two accepted payloads

**A. Daily station standee QR** — generated by staff *Today's Operations* card (`daily-queue-qr-dialog.tsx:37-55`), 600px, "Valid Today Only":

```
{origin}/queue-checkin?type=clinic-queue&date=<YYYY-MM-DD>&station=cvo-carmen&token=cvo-queue-<YYYY-MM-DD>
```

No pet / owner / queue data in the QR.

**B. Appointment pass QR** — on the appointment slip (`procedure-appointment-slip-dialog.tsx:77-92`), 160px, **JSON**:

```json
{
  "appointmentId": "...",
  "service": "...",
  "pet": "...",
  "date": "YYYY-MM-DD",
  "facility": "CVO Central Clinic, Cagayan de Oro"
}
```

Only `appointmentId` and `date` drive routing; `pet` is a name, not an id.

### Where scanned

- `ScanQueueQrDialog expectedType="queue"` — queue tracker (`Scan QR`, `Scan QR to Rejoin`) and pet-owner page (`Scan Station QR to Join Queue`, `Scan Reception QR to Enter Queue`).
- `PetQueueCheckInDialog` — dedicated in-place check-in for an "unofficial" transaction (`pet-queue-checkin-dialog.tsx`).

### Validation rules (`validateQueueQr`, `qr-validation.ts:139-177` + landing page)

1. Reject `field-op` → **"Field Operation QR Detected"** — *"...cannot be used to join Today's Clinic Queue."*
2. Accept only `queue` or `appointment`; reject `unknown` → **"Invalid Clinic Check-in QR"**.
3. `date` must equal today → **"Check-in QR Not Yet Active"** / **"Expired Check-in QR"**.
4. **Before 8:00 AM:** reject → **"Clinic Not Open Yet"** (enforced in scanner, landing page, and `checkInPetOwnerToQueue`).
5. **After 6:00 PM:** `isClinicQueueClosed()` → synthetic `overdue` ticket, no queue entry.
6. Landing page additionally rejects `type` containing `outreach` **or any `opId`**, stale `date`, missing booking, or an `appointmentId` not in today's eligible items.
7. Requires Clerk sign-in even though `/queue-checkin` is a public middleware route.

### On successful scan

- Appointment pass → navigate `/queue-checkin?date=<date>&appointmentId=<id>`.
- Station QR → navigate to the URL encoded in the QR.
- Landing page `checkInPetOwnerToQueue()` (`cvo-queue.ts:841-903`):
  - dedups by `appointmentId` / `encounterNo` / owner+pet; `skipped` or `overdue` tickets are removed and reissued a **fresh** number.
  - ticket number `Q-NNN` from max `queueSequence + 1`; id `ticket_<epoch>_<random4>`; `status: "waiting"`, `checkedInVia: "qr"`.
  - writes `queue_tickets` (upsert on `date, ticket_number`), localStorage `syncvet_clinic_queue_<date>`, and broadcasts on `cvo-queue-realtime-channel`.
  - updates `appointments.status = "checked-in"` or `consultations.status = "waiting"`.
  - renders boarding pass with ticket number, check-in time, "Now Serving" and "Ahead of You".

### Current web gaps to fix in mobile

- `token=cvo-queue-<date>` is **never verified** and is predictable; it is only a classification hint. No one-time use or signature.
- Ticket numbers are allocated client-side from max sequence → race condition. Allocate server-side.
- Device-clock dependence for the 8 AM / 6 PM gates.

## 3. Side-by-side comparison

| Aspect | Field Operation Attendance | Today's Clinic Queue |
| --- | --- | --- |
| Payload type | URL with query params | URL with query params **or** JSON appointment pass |
| Identity marker | `type=outreach-attendance`, `opId`, path `/outreach-checkin` | `type=clinic-queue`, `station`, `token=cvo-queue-*`, path `/queue-checkin`, or JSON `appointmentId` |
| What it identifies | An **outreach event** (`opId`) | A **clinic day + station** or an **appointment** |
| Time gate | Event date only; 1-day staff grace (scanning still event-day only) | Today only; **8 AM–6 PM** operating window |
| Primary side effect | `field_operations.vaccinated_pets + 1` | New `queue_tickets` row `Q-NNN` |
| Follow-up | Select pet + service → create completed `consultations` + audit log | Boarding pass; staff later call / complete / skip |
| DB tables written | `field_operations`, `consultations`, `audit_logs` | `queue_tickets`, `appointments`, `consultations` |
| Pet / owner in QR | No — chosen in form | No — derived from signed-in user + DB lookup |
| Scanning UI copy | "Scan Outreach Attendance QR" / "Scan the Outreach Attendance Poster" | "Scan Clinic Queue QR" / "Scan the Reception Counter Standee" |
| Wrong-family rejection | Rejects `queue` / `appointment` | Rejects `field-op` |

## 4. Cross-flow isolation rules to implement in mobile

1. **Classify before any side effect.** Run `parseQrCode()` on the raw decoded string first; never act on raw text.
2. **Gate the scanner by intended flow** (`expectedType: "queue" | "field-op"`). A scanner opened from the outreach screen must call only the field-op validator, and vice versa. The generic `"any"` scanner must still branch on parsed `kind`.
3. **Both validators explicitly reject the other family** with distinct user-facing errors. Keep the wording from `qr-validation.ts` so support can identify the mistake.
4. **Re-validate on the destination screen** — do not trust the scanner alone. `/queue-checkin` rejects `opId` / `outreach`; `/outreach-checkin` shows "Clinic Queue QR Detected".
5. **Deep links must be family-aware.** Map `.../queue-checkin?...` → queue check-in screen and `.../outreach-checkin?...` → outreach attendance screen inside the app. Never fall through to a generic web view.
6. **Unknown QR is always an error**, never silently routed into either check-in.
7. Pet-passport (`/verify/pet/:id`) and certificate (`/verify/certificate/:number`) QRs are **verification links, not check-in codes** — `qr-validation.ts` classifies them as `unknown`. Keep them out of both scan flows.

## 5. Mobile porting checklist

- [ ] Port `parseQrCode`, `validateQueueQr`, `validateFieldOpQr`, `formatQrDate` verbatim; keep `field-op` classification precedence.
- [ ] Camera: rear-facing, ~10 fps, centered square scan box; support gallery / file import with downscale + native detector fast path.
- [ ] Use a **single authoritative time source** (server / `Asia/Manila`) for "today", 8 AM open, 6 PM close, and outreach date / grace checks — not device local time.
- [ ] Use **authenticated writes** (Clerk JWT → Supabase or server API). `requirements.md:124-135` explicitly forbids relying on the anon public client for mobile writes.
- [ ] Field ops: add persistent exactly-once dedup (`opId + petId + date`) and eliminate the two-increment path.
- [ ] Queue: server-allocate `Q-NNN` sequences; replace the predictable `cvo-queue-<date>` token with a signed, short-lived token if security matters.
- [ ] Keep the two confirmation UX flows separate and keep the distinct error copy for wrong-family scans.
